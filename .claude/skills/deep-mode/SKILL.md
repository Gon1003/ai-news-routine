# 深考モード

人に読ませる成果物を作るとき、または考えを深めたい相談のときに、以下の順で進める。基本方針（CLAUDE.md / docs/system-prompt.md）は前提として守る。

## 1. 依頼を固める

次の4点を、依頼文と文脈から埋める。

- 目的：誰が、何のために使うか
- 最終形：媒体・形式・分量
- 制約：トーン・NG事項・締切など
- 判断基準：何ができていれば「良い」か

埋まらない項目のうち、成果物を大きく左右するものだけを、まとめて1回で質問する。それ以外は仮定を置き、置いた仮定を明記して進める。

## 2. 材料を集める

事実・数字・最新の動向・固有名詞が絡む場合は、書き始める前に検索や資料で確かめ、出典を控えておく。確かめられなかったことは、本文で未確認と分かるように書く。

## 3. 方向性を広げる（企画・コピー・構成・壁打ち）

方向性の違う案を3〜4つ、それぞれ1〜2行（狙いと、読む人にどう効くか）で出し、推す案を理由付きで1つ示す。

- ユーザーが「おまかせ」「進めて」と言っている場合や、自律的に作業している場合は、推す案で次に進む。それ以外はユーザーの選択を待つ。
- 壁打ちでは、案に加えて、ユーザーの考えの弱点・反論・見落としを率直に伝える。同意を優先しない。案と論点を返したところで止めてよい。
- 言い換えや定型の修正など、広げる必要がない作業では省略する。

## 4. 書く

選ばれた方向性だけで書く。頼まれていない拡張・装飾はしない。

## 5. 仕上げ点検（人に読ませる成果物）

出す前に以下を確認し、当てはまらない箇所を直してから出す。

- [ ] 冒頭で結論・要点が分かる
- [ ] 作業中の略語・内輪の言い回し・矢印の羅列が残っていない
- [ ] 初めて読む人が分かる（知らない前提を置いていない）
- [ ] 読む人の次の行動に関係ない情報（選ばなかった案の経緯など）を削った
- [ ] 文字数・トーン・媒体の制約を守っている
- [ ] 事実・数字は確かめてある。確かめていないものは未確認と書いてある

## 6. 学びを残す

ユーザーから修正や好みの指定を受けたら、今後も適用すべきものを `docs/lessons.md` に「〜する（理由：〜）」の形で追記する。ファイルがない環境では、ユーザーに「今後も適用するルール」として一文で示す。

## 呼び出し例

- 「deep-modeで、今週のAIニュースをnote記事にまとめて」
- 「deep-modeで、このキャンペーンのコピーを考えて」
- 「deep-modeで、この企画を壁打ちしたい」
