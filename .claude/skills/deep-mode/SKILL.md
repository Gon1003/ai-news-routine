# 深考モード（Deep Mode）

このSkillが呼ばれたら、以下の5ステップを順番に実行する。各ステップは
条件に応じてスキップ可だが、スキップする場合は理由を一言添える。

## Step 1｜意図確認

依頼に目的・最終形・制約が明示されていない場合、作業を始める前に
目的を一言で確認するか、代表的な解釈を2つ提示してユーザーに選ばせる。

すでに以下の意図明示テンプレートの内容が渡されている場合はこのステップを飛ばす。

```
【目的】これは何のためのものか
【最終形】理想的にはどういう状態になっていてほしいか
【制約】守ってほしい条件（文字数・トーン・NG事項など）
【依頼】具体的にやってほしいこと
```

## Step 2｜思考の深さを上げる

表面的な即答をしない。内部でしっかり筋道を立ててから出力する
（effort: high 相当。特に難しい判断が絡む場合は xhigh まで上げる）。

## Step 3｜発散フェーズ（企画・コピー・アイデア・壁打ちのみ）

本文をすぐに書き始めない。まず3〜4案を、それぞれ一言の理由付きで提示する。

- ユーザーが1案を選ぶ、または複数案を組み合わせる指示を待ってから次へ進む。
- 「壁打ち」目的で発散だけを求められている場合はここで止めてよい（本文化しない）。
- 定型作業（SNS定型文の軽い修正など）で明らかに発散が不要な場合はこのステップを省略する。

## Step 4｜本文作成

選ばれた方向性のみで本文を作成する。頼まれていない拡張・リファクタ・
過剰な装飾はしない。シンプルさを優先する。

## Step 5｜納品前チェック（人に読ませる成果物のみ）

出力前に以下を自己点検し、該当箇所があれば直してから出す。壁打ちのような
往復会話には適用しない。

- [ ] 作業中の省略語・内輪の言い回しが残っていないか
- [ ] 読者が初見で理解できる文章になっているか（前提知識を勝手に仮定していないか）
- [ ] 選ばなかった選択肢の説明など、読者に不要な情報が混ざっていないか
- [ ] 結論・要点が冒頭にあるか
- [ ] 文字数・トーンの制約を守っているか

## 使用例

- 「deep-modeでnoteの構成案を考えて」
- 「deep-modeでこのキャンペーンのコピーを3案出して」
- 「deep-modeでこの企画について壁打ちしたい」
- 「deep-modeでこのレポートの下書きを仕上げて」
